# Перенос бота на новый сервер (37.27.13.102)

Инструкция для переноса `purchases_bot` со старого сервера на новый через
GitHub (код) + WinSCP (данные, секреты). Docker на новом сервере уже
настроен, доступ — sudo.

## Важно: почему старый сервер нужно остановить ДО запуска нового

Бот работает через long polling (`getUpdates`). Если два процесса с одним
и тем же `BOT_TOKEN` одновременно опрашивают Telegram, они начинают
конфликтовать — Telegram отдаёт обновления то одному, то другому,
в логах сыплются ошибки, часть сообщений может дублироваться или теряться.

Поэтому порядок такой: **сначала останавливаем старый, потом запускаем
новый** — не наоборот, как можно было бы подумать из «после переноса
остановить старый». На практике это ничего не меняет: старый всё равно
не будет работать параллельно с новым, а так мы просто исключаем
переходный момент, когда оба активны одновременно. Заодно это даёт
безопасный, «замороженный» снимок базы данных для переноса — она не
меняется, пока идёт копирование.

Простой не страшен: сообщение группы «🛒 Присоединиться» и объявления
никуда не денутся, они просто не будут кликабельны пару минут, пока идёт
перенос.

## Шаг 1. Остановить бота на старом сервере

```bash
ssh <user>@<старый_сервер>
cd /opt/purchases_bot
sudo docker compose down
```

Проверить, что контейнер действительно остановлен:

```bash
sudo docker compose ps
```

## Шаг 2. Забрать данные со старого сервера через WinSCP

С этого момента база больше не меняется — можно спокойно копировать.

Подключитесь WinSCP к старому серверу и скачайте на Windows-машину:

| Файл на сервере | Зачем | Обязательно? |
|---|---|---|
| `/opt/purchases_bot/.env` | все секреты: `BOT_TOKEN`, `BOT_USERNAME`, `MAIN_GROUP_ID`, `ADMIN_TELEGRAM_IDS` и т.д. | да |
| `/opt/purchases_bot/data/bot.db` | вся боевая база: пользователи, закупки, участники, согласия с правилами | да |
| `/opt/purchases_bot/settings.ini` | бизнес-настройки (лимит закупки, пошлина) — **только если** на сервере их правили вручную и не коммитили | проверить (см. ниже) |

Остальное (`logs/`, `backups/`, сам код) переносить не нужно — код приедет
из GitHub, логи не нужны, актуальный бэкап вы и так сейчас делаете руками.

**Проверка `settings.ini`** — на старом сервере:

```bash
cd /opt/purchases_bot
git status settings.ini
```

Если пусто (`nothing to commit`) — файл не менялся локально, брать его
через WinSCP не нужно, он и так приедет из GitHub. Если показывает
изменения — скачайте его тоже и позже положите поверх склонированного.

## Шаг 3. Подготовить новый сервер

```bash
ssh <user>@37.27.13.102
docker --version
docker compose version
```

Оба должны отработать без ошибок — раз Docker уже настроен, всё готово.

```bash
sudo mkdir -p /opt/purchases_bot
sudo chown $USER:$USER /opt/purchases_bot
```

## Шаг 4. Склонировать репозиторий с токеном

```bash
git clone https://<GITHUB_USERNAME>:<GITHUB_TOKEN>@github.com/Lightwell-bg/purchases_bot.git /opt/purchases_bot
cd /opt/purchases_bot
```

Токен в URL остаётся в `.git/config` в открытом виде — сразу после клона
уберите его оттуда, дальнейшие `git pull` и так будут работать по SSH-ключу
или через сохранённые Git-креды, либо токен можно ввести заново при
следующем pull:

```bash
git remote set-url origin https://github.com/Lightwell-bg/purchases_bot.git
```

## Шаг 5. Залить данные через WinSCP

Подключитесь WinSCP к новому серверу (37.27.13.102) и загрузите то, что
скачали на шаге 2, в те же относительные пути:

```
.env                → /opt/purchases_bot/.env
data/bot.db         → /opt/purchases_bot/data/bot.db
settings.ini        → /opt/purchases_bot/settings.ini   (только если скачивали на шаге 2)
```

Каталог `data/` создастся автоматически при первом запуске, если его нет —
но раз вы кладёте туда файл, можно создать заранее:

```bash
mkdir -p /opt/purchases_bot/data /opt/purchases_bot/logs
```

## Шаг 6. Сверить `.env`

На новом сервере:

```bash
cd /opt/purchases_bot
diff <(sed -E 's/=.*/=<V>/' .env) <(sed -E 's/=.*/=<V>/' .env.example)
```

Пустой вывод — всё синхронно. Если diff не пустой, значит в коде появились
переменные, которых не было на старом сервере на момент последнего
бэкапа `.env` — доберите их значения вручную (см. `README.md`, раздел
«Настройка .env»).

## Шаг 7. Запустить

```bash
sudo docker compose build
sudo docker compose up -d
sudo docker compose logs -f --tail=50
```

В логах должно быть `Bot started as @<username>` и применённые миграции
(`Database migrations applied`) — без `TelegramUnauthorizedError`.
`Ctrl+C` выходит из просмотра логов, контейнер продолжает работать.

## Шаг 8. Проверить перенос данных

В Telegram, от своего аккаунта:

- `/my` в личке с ботом — должны быть видны те же закупки, что были на
  старом сервере;
- `/stats` (если вы администратор) — числа пользователей и закупок должны
  совпадать с тем, что было на старом сервере до остановки;
- откройте любое старое объявление в группе — кнопка «🛒 Присоединиться»
  должна снова открывать бота и работать как раньше (это тот же бот,
  тот же `BOT_TOKEN` — просто теперь отвечает с нового сервера).

## Шаг 9. Окончательно вывести старый сервер из эксплуатации

Старый бот уже остановлен с шага 1, ничего дополнительно делать не нужно.
Рекомендация: не удалять `/opt/purchases_bot` на старом сервере сразу —
подержите его пару дней как холодный бэкап на случай проблем с переносом,
затем удалите или заархивируйте по своему усмотрению.

Если старый сервер выводится из эксплуатации целиком — ничего дополнительно
настраивать не нужно: бот работает через long polling, входящих портов
не открывает, DNS/файрвол не трогает.

---

## Если что-то пошло не так

Откатиться на старый сервер:

```bash
ssh <user>@<старый_сервер>
cd /opt/purchases_bot
sudo docker compose up -d
```

⚠️ Если к этому моменту новый сервер уже успел поработать и принять новые
закупки/заявки — они окажутся только в базе нового сервера. Возврат к
старому означает потерю этих данных, если их не перенести обратно тем же
способом (WinSCP: `data/bot.db` с нового сервера на старый). Поэтому
после того, как новый сервер подтверждённо заработал (шаг 8 пройден) —
считайте его основным и не запускайте старый одновременно с ним.
